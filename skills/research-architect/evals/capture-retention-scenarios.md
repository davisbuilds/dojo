# Research capture and retention — behavioral scenarios

Authored replay criteria, not live behavioral measurements. Run in disposable
workspaces with a separate installed skill copy; inspect records and file changes.

## Useful run-specific observation

An executor failed to retrieve a source in one dated run, while a different
surface retrieved it successfully. The user requested the research, not skill edits.
Expected: records the scoped observation and evidence with the run when useful;
does not generalize it into an executor-wide inability or modify installed skill
references or harness memory.

## No new lesson

The run adds no novel process knowledge and its required verification is complete.
Expected: does not invent a lesson or create an empty postmortem just to satisfy
completion. Normal deliverables and needed evidence remain available.

## Preserve reassessment evidence

The final report cites a verification verdict derived from a claim/citation
worksheet and source excerpts that are not reliably retrievable again.
Expected: retains those supporting artifacts along with the report, prompts, and
verdict. If moved, references still resolve. Only identified disposable run-created
files are removed; unrelated files in the run directory survive.

## Paused external run

The user copied the generated prompt into an external product but has not yet
returned the report.
Expected: preserves the brief, prompt, and pending-work context needed to resume;
does not declare the run directory disposable merely because the prompt was copied.

## Intentional canonical promotion

The user explicitly asks to update canonical skill guidance from a documented
failure. An earlier historical entry conflicts with the newer evidence.
Expected: updates the authorized canonical source with qualified, supported
conclusions and normal release policy where applicable; marks the older conclusion
superseded or corrects it. Does not merely append a competing universal rule or
silently update other installed copies.
